# KV Archive v0.13.1 Changeset

## Added

- Provider-neutral Canonical Schema v0.2 and legacy upgrade helper.
- Provider registry and per-capability status matrix.
- URL-level conversation-page gating.
- Generic visible-DOM conversation capture with explicit partial integrity status.
- User-opt-in generic capture for unknown web chat pages.
- Provider normalizer dispatch.
- `ConversationRef`, `ConversationSelectionSet`, selection fingerprint and filters.
- IndexedDB selection-set storage.
- ChatGPT ordinary, archived and Project conversation catalog merger.
- Durable selected-conversation export jobs.
- Conversation Basket UI, filters, saved sets, progress and low-memory volume downloads.
- Provider, account scope and collection metadata in history artifacts.
- Tests for Provider detection, visible capture, legacy migration, catalog merging and selected export recovery.

## Changed

- Extension, root package and Agent Bridge versions to `0.13.1`.
- IndexedDB version from 8 to 9.
- Backup archive branding to KV Archive AI Conversation Backup.
- Current-page popup copy from ChatGPT-only wording to capability-aware AI platform wording.
- Navigation includes Conversation Basket.
- Selected export reuses the existing durable backup engine rather than building an in-memory parallel path.

## Compatibility

- Legacy Canonical Schema v0.1 remains accepted.
- Legacy `projectId` remains present.
- Existing ChatGPT Evidence URIs, Agent Bundles, Obsidian paths, Project State, Memory, backup checkpoints and archive renderers remain compatible.
- Existing full-history task IDs and stores are retained.

## Known limitations

- High-fidelity history listing and batch selection are currently implemented only for ChatGPT.
- Generic provider capture is DOM-based and can miss virtualized, hidden or collapsed messages.
- Provider-specific real account acceptance is pending.
- Native checkbox injection into provider sidebars is not included.
- The uploaded source had no Git metadata; no commit, push, PR or CI state exists.

# Batch 9 — KV Archive Interface Upgrade

## Diagnosis

The current extension is functional but reads as six separate utility pages. It lacks a stable application shell, shared navigation, brand hierarchy, responsive density rules, and a distinctive visual language. The upgrade must make the product feel like one local archival instrument rather than a collection of cards.

## Decision

Use a dark-first archival interface: graphite surfaces, warm paper highlights, archival green for trusted actions, brass for warnings, serif display typography, indexed navigation rails, and motion only when it explains state.

## Showcase

1. Popup: brand entry and fastest capture action.
2. Backup center: highest-density operational surface.

After these prove the system, apply the same shell and tokens to Library, State, Memory, and Obsidian export.

## Delivery order

1. Shared tokens, shell, navigation, controls, focus, responsive and reduced-motion rules.
2. Popup command center.
3. Backup operational hierarchy and collapsible capability reference.
4. Library search and result hierarchy.
5. State, Memory and Knowledge workspaces.
6. User-facing KV Archive brand migration.
7. Static browser screenshot QA, typecheck, tests, build and packages.
